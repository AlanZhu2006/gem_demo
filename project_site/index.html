GEM uses the geometry of past observations to help existing navigation policies
return to previously seen places, without additional training.

The idea

Past views become useful again.

A goal image may show a place the robot saw much earlier, beyond its controller’s short observation context. GEM retrieves a supporting view from that history, verifies the match geometrically, and relates the remembered goal to the current camera—even when the goal and current images do not overlap.

02 / Method

A geometric bridge through history

Persistent geometry. Verified recall.
Frozen navigation policies.

A streaming geometry model relates past and current observations in a shared coordinate frame. GEM pairs that state with an indexed image archive, then reads out a verified historical view or a goal bearing through the controller’s existing interface.

Figure 1 / System architecture

One memory, two readouts

Sparse readout supplies verified recall for goal conditioning. Dense readout supplies current monocular depth for local control. The geometry model and navigation policies remain frozen.

1

Retain experience

Keep the streaming working state and indexed RGB–geometry archive across goals.

2

Verify the recall

Retrieve a supporting view and estimate the goal pose from image matches and archived depth.

3

Guide the controller

Read the goal relative to the current camera. If verification fails, preserve the native inputs.

Scope and limitations

Recall requires verifiable historical support. Pose drift can distort the bearing, and a bearing alone cannot describe long detours around obstacles. Archived observations also grow with episode length.

See the paper for protocol, ablations, and limitations.
